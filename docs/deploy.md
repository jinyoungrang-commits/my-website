# 공개 사이트 배포

이 앱은 화면과 팀방 API를 함께 실행하는 Node.js 서비스입니다. GitHub 저장소 연결만으로는 공개 사이트 주소가 생기지 않습니다. 기존 `.chatgpt.site` 주소는 다른 계정의 배포이므로, 새 호스팅에서 새 주소를 발급받습니다.

## Render에서 시작하기

1. Render에서 본인의 GitHub 계정으로 가입하거나 로그인합니다.
2. 아래 배포 시작 링크에서 `jinyoungrang-commits/my-website` 저장소 접근을 허용합니다.
3. Blueprint의 `dagachi-campus` 웹 서비스와 1GB 영구 디스크, **화면에 표시되는 요금**을 확인합니다. 이 구성은 유료 Starter 서비스와 영구 디스크를 사용합니다. 계정 생성과 결제는 자동으로 수행하지 않습니다.
4. 직접 배포를 실행합니다. `Live` 상태가 되면 서비스 화면에 표시되는 `https://…onrender.com` 주소가 실제 사이트 주소입니다. 이 문서에서 발급되지 않은 주소를 미리 만들어 안내하지 않습니다.
5. 발급된 주소에서 첫 화면의 로고를 확인하고, 예시 팀방을 만든 후 다른 브라우저에 팀원 초대 링크를 붙여 넣어 참여를 확인합니다.

[Render 배포 시작](https://render.com/deploy?repo=https://github.com/jinyoungrang-commits/my-website)

배포 시작 링크는 배포 설정 화면입니다. 아직 생성되지 않은 사이트의 주소가 아닙니다.

`render.yaml`의 `DATA_DIR=/var/data`와 디스크의 `mountPath`가 일치해야 합니다. 무료 웹 서비스로 변경하면서 영구 디스크를 제거하면 SQLite 데이터가 재배포 또는 인스턴스 교체 시 사라질 수 있으므로, 데이터가 유지되는 동일한 구성으로 간주하지 마세요.

## 배포 구성

- `.node-version`과 `NODE_VERSION`: Node.js 24에서 빌드하고 서버를 실행합니다.
- `render.yaml`: 웹 서비스, API 상태 확인, 포트, 영구 데이터 저장소를 함께 정의합니다.
- `/api/health`: 준비된 서버에서 `{"ok":true}`를 반환합니다.
- 실제 코드·로고·화면 데이터는 같은 서비스에서 제공합니다. 다른 계정의 서버에 의존하지 않습니다.
- 현재 개발 환경의 `.data`나 로컬 브라우저 로그인 정보는 GitHub에 올리지 않습니다. 새 공개 서비스에서 팀방을 새로 만드세요.

## 다른 호스팅을 사용할 때

Node.js 24 실행과 영구 저장 공간을 지원하는 호스팅을 사용할 수 있습니다. `npm ci --include=dev` 및 `npm run build` 후 `npm start`로 실행합니다. 포트 10000으로 요청을 전달하고, `DATA_DIR`를 영구 저장 공간의 경로로 설정하세요. 제공자가 별도 포트를 요구하면 `PORT`를 설정합니다. 도메인과 HTTPS 인증서는 선택한 호스팅에서 연결합니다.
