# 다가치 — 더 가치 있는 팀플

제공된 원본 사이트 캡처를 기준으로 재구성한, 직접 수정할 수 있는 웹사이트입니다. 공개 소개 페이지와 실험실, 과제 예시 플랜, 팀방의 다섯 탭을 포함합니다. 이전 계정이나 이전 배포 서비스에 의존하지 않습니다.

## 실행하기

Node.js 24 이상이 필요합니다. 별도 데이터베이스 설치나 API 키는 필요하지 않습니다.

```bash
cd /workspace/my-website
npm ci --cache /tmp/dagachi-npm-cache
npm run dev
```

개발 화면은 포트 **5173**, API 서버는 **3001**에서 실행됩니다. 개발 중에는 화면의 코드 변경이 자동 반영됩니다. 서버 코드를 변경하면 개발 명령을 다시 실행하세요.

배포용으로 실행하려면:

```bash
npm run build
npm start
```

배포용 서버는 기본 포트 **3000**에서 프런트엔드와 API를 함께 제공합니다. `PORT`로 포트를, `DATA_DIR`로 저장 폴더를 바꿀 수 있습니다. 정적 파일만 배포하면 팀방 기능은 작동하지 않습니다. Node 서버 실행이 가능한 호스팅과 쓰기 가능한 영구 저장 공간이 필요합니다.

## 어디를 수정하나요?

| 수정할 내용                        | 파일                                        |
| ---------------------------------- | ------------------------------------------- |
| 소개 페이지 문구·섹션              | `src/pages/Landing.jsx`                     |
| 실험실·팀 생성·입장·예시 일정 화면 | `src/pages/Lab.jsx`                         |
| 팀방의 할 일·활동·팀원·평가·초대   | `src/pages/Team.jsx`                        |
| 색상·폰트·여백·모바일 디자인       | `src/styles.css`                            |
| 로고                               | `public/dagachi-logo.jpg`                   |
| 공통 헤더·푸터·개인정보·문의 창    | `src/main.jsx`                              |
| 화면에 표시하는 예시 일정          | `src/api.js`의 `sampleTasks`                |
| 서버의 예시 일정 생성·저장·권한    | `server/index.mjs`의 `tasksFor` 및 API 처리 |

기본 연두색은 `src/styles.css` 최상단의 `--lime`, 글자색은 `--ink`에서 바꿀 수 있습니다. 한글 폰트는 패키지로 설치하여 같은 서버에서 제공하므로, 이용자의 외부 폰트 서비스 연결이 필요하지 않습니다.

## 직접 체험하기

1. 첫 화면의 **팀 생성하기**를 누릅니다.
2. **예시 과제로 체험하기**에서 3주짜리 일정을 확인합니다.
3. **팀원 초대하고 시작하기**를 누르고 이름과 저장·공유 동의를 입력합니다.
4. 자료조사·아이디어·PPT·발표 중 선호하는 일을 1~2개 저장합니다.
5. **현재 인원으로 역할 추천**을 누릅니다. 선호와 할 일 수를 참고해 배정하며, 팀장이 담당자와 기한을 수정할 수 있습니다.
6. **오늘 우리 팀**에서 할 일 추가·완료·진행 상태를 바꾸고 일정을 저장합니다.
7. **활동 기록**, **팀원과 역할**, **상호 평가**, **초대** 탭을 사용합니다.
8. **초대**에서 팀원용 `M-` 코드와 교수님용 `P-` 코드를 복사합니다. 다른 브라우저나 다른 기기에서 같은 서버에 접속하여 코드를 입력하면 참여할 수 있습니다.

일반 **새 팀 만들기**는 빈 팀방을 생성합니다. 역할 추천 후 실제 할 일을 직접 추가하세요. 원본과 같이 이미지·텍스트 AI 과제 분석은 **준비 중**이며, 선택한 이미지는 미리보기만 하고 서버로 업로드하지 않습니다.

## 데이터와 접근 권한

- 데이터는 기본적으로 `.data/dagachi.sqlite`에 보관됩니다. 재시작해도 팀방·활동·평가·일정·참여 인증이 유지됩니다. `.data`는 Git에 포함되지 않습니다.
- 같은 브라우저의 로컬 저장소에 팀방 입장 정보가 남아 실험실에서 다시 열 수 있습니다. 이 저장소를 지우면 입장 정보도 사라집니다. 팀장 재입장을 위해서는 브라우저 데이터를 유지해야 합니다. 초대 코드는 새로운 팀원 또는 열람 세션을 만듭니다.
- 팀장은 팀 일정·담당자·모든 할 일을 관리합니다. 팀원은 자신의 할 일과 프로필, 활동·평가를 작성합니다. 교수님은 읽기만 할 수 있습니다.
- 상호 평가는 팀장·교수님과 작성자만 볼 수 있습니다. 평가자 이름은 교수님에게만 표시되도록 서버에서 응답을 제한합니다.
- 별도의 계정 로그인이나 계정 복구는 없는 체험판입니다. 초대 코드는 접근 권한을 부여하므로 공개하지 마세요.
- 사전 신청·문의는 서버에 저장됩니다. 이메일 발송과 운영자 알림은 연결하지 않았으며 관리자 화면은 없습니다. 실제로 운영하려면 관리·삭제 정책과 운영자 처리 흐름을 추가하세요.
- 기존 사이트의 비공개 데이터와 원본 계정의 배포 권한은 복구하거나 이전하지 않았습니다. 로고는 원본 사이트의 `dagachi-logo.jpg` 파일을 그대로 사용합니다.

서비스 데이터의 백업에는 실행 중인 SQLite 파일을 단순 복사하지 말고 SQLite의 온라인 백업 기능을 사용하거나 서버를 정지한 상태에서 `.data` 폴더 전체를 복사하세요. 기존 데이터를 삭제하거나 덮어쓰지 마세요.

## 검증

```bash
npm run test:api
npm run build
npm test
```

API 검증은 별도 임시 데이터베이스를 사용하며, 초대·권한·배정·활동·평가·재시작 보존을 확인합니다. 브라우저 검증은 Chromium을 사용해 데스크톱·모바일·팀원·교수님 흐름을 확인합니다. 시스템 Chromium의 기본 경로는 `/usr/bin/chromium`이며 다른 환경에서는 `CHROMIUM_PATH`를 설정하세요. 브라우저 테스트는 포트 3110, API 테스트는 포트 3109를 사용합니다. 테스트 데이터는 실제 서비스의 `.data`에 기록하지 않습니다. 브라우저 테스트의 결과 화면은 `test-results`에 저장됩니다.

캡처 분석 및 재현 범위는 `docs/recreation.md`에 기록했습니다. 유료 Render 서비스·디스크 설정은 사용자의 요청에 따라 제거했습니다. 무료 공개 배포의 선택지와 계정 구분은 `docs/deploy.md`를 참고하세요. GitHub에 코드를 올리는 것과 외부 사이트 배포는 별도의 단계입니다.
